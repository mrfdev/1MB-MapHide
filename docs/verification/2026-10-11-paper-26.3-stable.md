## Compatibility review and changes

Reviewed official [project setup](https://docs.papermc.io/paper/dev/project-setup/), [Java requirements](https://docs.papermc.io/paper/getting-started/), [plugin.yml](https://docs.papermc.io/paper/dev/plugin-yml/), [plugin lifecycle](https://docs.papermc.io/paper/dev/how-do-plugins-work/), [scheduling](https://docs.papermc.io/paper/dev/scheduler/), [event priority/cancellation](https://docs.papermc.io/paper/dev/event-listeners/), and [roadmap](https://docs.papermc.io/paper/dev/roadmap/). Paper 26.3 requires Java 25 or newer, so the existing Java 25 toolchain and bytecode target remain appropriate.

Exact-build Javadocs confirm the JavaPlugin enable/disable lifecycle, synchronous Runnable scheduler overloads, exact local online-player lookup, Bukkit permissions, `getPluginMeta`, and configuration comment APIs used here. Adventure remains 5.2.0. Compilation emitted no deprecation diagnostics; the runtime suite checks linkage on the actual stable server. No plugin Java-source changes were needed for stable compatibility. Commands, permission definitions, translations, configuration schema, stored visibility ownership, plugin identity (`1MB-MapHide`), and main class remain unchanged; the descriptor keeps `api-version: '26.3'`.

MapHide uses Bukkit permissions and authoritative `Player#getUniqueId()` values for BlueMap visibility and timer state. It has no LuckPerms command/API integration or external identity lookup. There are no inventory menus, custom items/PDC, economic transactions, database operations, NMS, or paperweight/dev-bundle dependencies in this project. Gameplay timer work remains on the Bukkit main-thread scheduler. Configuration and translation reloads retain their existing synchronous file I/O; this migration does not establish slow-storage performance or asynchronous PlaceholderAPI consumer safety. Folia support is not verified by these Paper tests.

Build and development changes:

- Pin Paper API, STABLE channel, build, and server checksum in `gradle.properties`; record resolved dependencies in `gradle.lockfile`.
- Use `servers/Paper-26.3-stable` for future development fixtures. Provision from the exact Fill record and fail on mismatched channel, size, or SHA-256. Existing destinations are never overwritten.
- Remove automatic deployment from `build`; explicit `deployServers` targets the selected development fixture. No existing server needed to stop for this build.
- Run fixture regression tests in Gradle `check` and CI. Enforce stable release pins and detect stale API/channel declarations in maintained documentation and AGENTS.md. Clearly dated historical records remain unchanged.
- Extend the smoke harness with separate process restarts, persistence assertions, optional PlaceholderAPI absence, and expected missing-BlueMap rejection. Preserve separate logs and failure reports.

The [global](https://docs.papermc.io/paper/reference/global-configuration/) and [world](https://docs.papermc.io/paper/reference/world-configuration/) defaults were reviewed. Generated stable-server configuration retains `false` for piston duplication, unsafe end portals, headless pistons, permanent-block exploits, disabled tripwire updates, and skipped tripwire-hook placement validation; oversized-component sanitizer exclusions remain `[]`. No permissive JVM flags or exploit-setting exceptions were added.

## Isolation and limits

The stable fixture reads only the previous local test fixture's accepted EULA, accepted BlueMap resource terms, plugin binaries, and runtime caches. It imports no worlds, player records, credentials, or existing plugin configurations. Every test process runs in a newly created disposable directory, with fresh worlds, localhost Minecraft binding, and disabled BlueMap HTTP/RCON/query listeners. Existing `servers/Paper-26.3`, `servers/Paper-26.2`, shared test-server files, production services, worlds, and databases are not changed or launched.

The tested plugin stack is MapHide, BlueMap runtime 5.27 (manifest 5.26), and PlaceholderAPI 2.12.3, plus the explicit dependency-absence scenarios. The [September verification](2026-09-25-paper-26.3.md) documents an older CMI/CMILib/BlueMap startup deadlock; the wider plugin combination has not been validated on this stable build. OSHI's unrecognized macOS 27 warning and BlueMap's plugin-induced-save notice are nonfatal third-party notices.

## Manual verification

1. Use a separate stopped test instance of the verified stable fixture. Install the built MapHide JAR (or run the explicit `deployServers` task), select an unused Minecraft port in its `server.properties`, retain `server-ip=127.0.0.1`, and launch with the selected JDK's `java -Xms512M -Xmx2G -jar paper.jar --nogui`. Stop with `stop`. Do not use the historical ALPHA launcher. For map-browser checks, configure a test-only BlueMap web listener on an unused port, restricted to local access, using BlueMap's supported configuration.
2. Connect a Java client and, in a separately configured Floodgate test stack, a `.bedrock` client. Record each actual server UUID. Exercise `/bmpc`, `/bmpc toggle`, `/bmpc show`, `/bmpc hide`, `/map hide`, and admin target commands. Confirm actual marker visibility and `%maphide_state%` agree, and exact names preserve the Bedrock prefix. Reconnect and restart to check BlueMap's stored player choices.
3. On test LuckPerms only, address permission changes by the actual server UUID, including for Bedrock and renamed accounts. Run `lp user <actual-server-UUID> permission set maphide.player.toggle false`, test `/bmpc toggle` and `/map hide`, and confirm denial leaves visibility unchanged; restore the test override with `lp user <actual-server-UUID> permission unset maphide.player.toggle`. Deny admin target permissions and check that other players are unaffected. MapHide itself issues no LuckPerms commands.
4. Run `bmpc config set forced-permissions.enabled true`. Check hide-only, show-only, both-node conflicts under each priority, permission removal, and the optional repeating check. Commands must respect forced state. Set a short delay with `bmpc config set toggle-back-after-seconds 2`; rapidly repeat toggles, issue explicit show/hide, disconnect, reconnect, change worlds, and stop/restart while a timer is pending. Confirm no stale timer or unwanted later visibility change.
5. Check first joins versus returning players with both default-visibility settings and both first-join-only modes. Check language fallback, custom translations, config comments/unknown keys, and reload while players are active. Test PlaceholderAPI through the actual scoreboard/chat consumers, including any asynchronous consumer; console null-player parsing alone does not verify those thread interactions.
6. Add LuckPerms, CMI, CMILib, Vault, and other intended integrations one at a time using fresh test configuration, with external integrations inactive. Verify startup, actual marker behavior, and shutdown after each addition. Do not infer full-stack compatibility from this console suite.

Inventory interactions, custom-item metadata, purchases, refunds, and transaction replay do not apply to MapHide's feature set. Player-connected permissions, live marker rendering, timer expiry, and asynchronous integration behavior were not claimed as automated passes.
