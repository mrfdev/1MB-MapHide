The PlaceholderAPI release notes describe 26.2 Paper support as experimental. Local results apply to the MapHide expansion and command workflows on the pinned Paper version. Zrips recommends updating CMI and CMILib together. An entitled download of CMI 9.8.12.0 was unavailable, so the latest pair remains unverified at runtime. MapHide's source uses Bukkit permissions, BlueMap, and the optional PlaceholderAPI expansion. [Zrips CMILib FAQ](https://www.zrips.net/cmilib/faq/)

The BlueMap 5.29 and CMILib 1.6.1.4 combination stalled before MapHide enabled and before CMI was installed. Two JVM thread dumps showed the server thread blocked on `CraftBlockData` class initialization while BlueMap's loading thread waited for `CraftBeehive` initialization. LuckPerms and the CMI Vault permission and chat hooks had already enabled. The disposable JVM required forced termination after the startup timeout and a failed normal stop.

Two control servers started and shut down cleanly. The MapHide, BlueMap, PlaceholderAPI, LuckPerms 5.5.92, and Vault 1.7.3-CMI control passed six checks, including MapHide status, placeholder parsing, and the permission provider and bridge diagnostics. The CMILib 1.6.1.4 control passed five checks with PlaceholderAPI, LuckPerms, and Vault and with BlueMap and MapHide absent.

The historical CMI 9.8.10.1 and CMILib 1.6.0.0 pair passed an isolated startup and shutdown alongside BlueMap 5.29, PlaceholderAPI 2.12.3, LuckPerms 5.5.92, and Vault 1.7.3-CMI. The run checked MapHide status, placeholder parsing, LuckPerms info, CMI's reported version, and clean shutdown. This is a fallback result from one run. The same older pair had exhibited a startup deadlock on a previous Paper and BlueMap stack. [Historical verification](2026-09-25-paper-26.3.md)
